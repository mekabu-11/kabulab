# 画面設計

## デザイン方針

- 記録の負担を最小化する
- 体調が悪い日でも迷わず入力できる
- 医療アプリではなく、生活改善の記録アプリとして落ち着いた印象にする
- AI提案は強く言い切らず、やさしいコーチの口調にする
- 重要な数字は大きく、入力ボタンは押しやすくする

## ナビゲーション

MVPではタブ + モーダル入力を基本にする。

```txt
Tabs
  - ホーム
  - 記録
  - 分析
  - 設定

Modal / Stack
  - 食事記録
  - 体調記録
  - 体重記録
  - 筋トレ記録
```

## ホーム画面

### 表示内容

- 今日の摂取カロリー
- 今日の目標カロリー
- 今日あと足したいカロリー
- 今日の体調ステータス
- AIからの一言提案
- 食事記録ボタン
- 体調記録ボタン
- 体重記録ボタン

### レイアウト案

1. 今日のカロリー概要
2. 残りカロリー
3. AIの一言
4. クイック記録ボタン
5. 今日の記録タイムライン

### 表示例

```txt
今日 1,740 / 2,400 kcal
あと 660 kcal

AI提案:
今日は脂質が少なめなので、夕方におにぎりかバナナを足すと胃腸負担を増やしにくそうです。

[食事] [体調] [体重]
```

## 食事記録画面

### 機能

- 写真アップロード
- テキスト入力
- AI解析実行
- 推定結果の表示
- ユーザー修正
- 保存

### 入力項目

- 写真
- 食事内容テキスト
- 食事時間
- 食事名
- kcal
- タンパク質
- 脂質
- 炭水化物
- 胃腸負担候補
- メモ

### UX方針

- 最初に「写真」または「テキスト」のどちらでも始められる
- AI解析中は途中離脱しても下書きが残る
- AI推定値には「AI推定」ラベルをつける
- 修正できる数値入力を明確にする
- 保存ボタンは画面下部に固定する

## 体調記録画面

### 機能

- 症状をワンタップ選択
- 発生時間入力
- メモ入力
- 保存

### 症状チップ

- 問題なし
- 下痢
- 便秘
- お腹の張り
- 胃もたれ
- 吐き気

### 危険症状

通常の症状とは別に「注意が必要な症状」として配置する。

- 血便
- 激しい腹痛
- 水分が取れない
- 高熱
- 急激な体重減少
- 下痢が長期間続く
- 嘔吐が続く

選択時は保存前に注意文を表示する。

## 体重記録画面

### 機能

- 体重入力
- 日付選択
- メモ入力
- 保存

### UX方針

- 数値入力を大きくする
- 前回体重を参考表示する
- 体重の増減に対して強すぎる評価をしない

表示例:

```txt
今日の体重
58.4 kg

前回: 58.2 kg
```

## 筋トレ記録画面

### 機能

- 実施日
- 種目名
- 時間
- 強度
- メモ

### 強度

- 軽め
- 普通
- きつめ

## 分析画面

### 表示内容

- 直近7日間の食事傾向
- 直近7日間の体調傾向
- 怪しい原因候補
- 今週試す改善案
- 増量ペースの確認

### レイアウト案

1. 7日間サマリー
2. 増量ペース
3. 体調傾向
4. 怪しい原因候補
5. 今週の小さな実験
6. 注意喚起

### 表示例

```txt
今週の傾向
摂取カロリーは目標より平均420kcal少なめです。

怪しい候補
乳製品やホエイを摂った日の翌朝に、お腹を壊す記録がやや多い傾向があります。

今週試すこと
ホエイを半量にして、豆乳か乳糖なし牛乳で試してみましょう。
```

## 色とトーン

- 背景: 明るいグレーまたは白
- メイン: 落ち着いたグリーン
- アクセント: 温かいイエロー
- 注意: 赤ではなく、まずはオレンジ系。ただし重大症状は明確に赤系も使う
- テキスト: 高コントラストの濃いグレー

## アクセシビリティ

- タップ領域は44px以上
- 色だけで状態を伝えない
- 数字と単位を明確に表示する
- AI提案は短く、長文は折りたたみにする
