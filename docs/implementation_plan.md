# 実装計画

## フェーズ1: プロジェクト初期化

目的:
Expo + Supabase の開発土台を作る。

作業:

- Expo React Native TypeScript プロジェクト作成
- Expo Router 設定
- ESLint / Prettier 設定
- Supabase Client 設定
- 環境変数設定
- 画面ルーティング雛形作成

成果物:

- 起動できるExpoアプリ
- ログイン前後のルーティング
- Supabase接続確認

## フェーズ2: Supabase設計反映

目的:
DB、認証、Storageの基盤を作る。

作業:

- Supabaseプロジェクト作成
- migrations作成
- `users`, `meals`, `body_conditions`, `weights`, `workouts`, `ai_suggestions` 作成
- RLS設定
- `meal-photos` Storage bucket作成
- Auth signup hook または初回ログイン時プロフィール作成

成果物:

- ユーザーごとにデータ分離されたDB
- 写真アップロード先

## フェーズ3: 手動記録機能

目的:
AIなしでも記録アプリとして使える状態にする。

作業:

- ホーム画面
- 食事手動記録
- 体調記録
- 体重記録
- 筋トレ記録
- 今日の摂取カロリー集計
- 直近ログ表示

成果物:

- 日々のログを保存・閲覧できる

## フェーズ4: 食事AI解析

目的:
写真またはテキストから食事推定を行う。

作業:

- Edge Function `analyze-meal`
- OpenAI Vision対応モデル連携
- AIレスポンスJSON schema
- 解析結果の編集フォーム
- 解析失敗時の手動入力フォールバック

成果物:

- 写真またはテキストから kcal / PFC / 胃腸負担候補を推定できる

## フェーズ5: 分析画面

目的:
直近7日間の傾向を可視化し、改善案を出す。

作業:

- Edge Function `analyze-trends`
- 直近7日間のログ取得
- AI傾向分析
- `ai_suggestions` 保存
- 分析画面表示
- 安全アラート表示

成果物:

- 怪しい原因候補と今週試す改善案を確認できる

## フェーズ6: MVP仕上げ

目的:
初期ユーザーが日常で使える品質にする。

作業:

- 入力導線の短縮
- ローディング、エラー、空状態
- iOS / Android 表示確認
- RLSテスト
- Edge Functionエラー確認
- README / setup更新

成果物:

- ローカルまたは開発環境で運用できるMVP

## 優先順位

1. DBと手動記録
2. ホーム集計
3. 食事AI解析
4. 体調傾向分析
5. UI改善
6. 通知やリマインダー

## リスクと対策

| リスク | 対策 |
|---|---|
| AIの栄養推定が不正確 | 必ずユーザー修正可能にする |
| 医療診断に見える | 表現ルールと安全文言を固定する |
| 入力が面倒で続かない | ワンタップ症状、写真優先、下書き保存 |
| OpenAI APIキー漏洩 | Edge Functionsに閉じる |
| RLS設定漏れ | migrationレビューと実ユーザーテスト |
| 写真アップロードが重い | 画像圧縮、必要ならリサイズ |

## 検証計画

- Expoアプリが起動する
- サインアップ、ログイン、ログアウトができる
- ユーザーAがユーザーBのデータを読めない
- 食事記録を保存できる
- 体調記録を保存できる
- 体重記録を保存できる
- 筋トレ記録を保存できる
- 食事写真解析が成功する
- AI解析失敗時に手動保存できる
- 危険症状で受診相談導線が出る
- 分析画面で7日間の傾向が表示される
